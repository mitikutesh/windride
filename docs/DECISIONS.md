| DEC-027 | **Strava upload: sanctioned GET + idb-stored secret** (WR-023). The story's acceptance criteria say "absolutely no Strava reads anywhere" / "no GET endpoints" — but Strava's upload API requires polling `GET /uploads/{id}` to learn the resulting `activity_id`; there is no non-GET way to obtain it. | DEC-028 | **Speed-model calibration design** (WR-024). (a) The fit calibrates only the 4 named params `{v0_road, v0_gravel, k_tail, k_head}`; grade coefficients are held fixed and the grade term is subtracted from observed speed before the weighted least-squares, keeping the fit a clean linear problem — physics (CdA/Crr) fitting is explicitly out of scope per the story. (b) Calibration is captured at ride-finish while the planned `CandidateAnalysis` is still in memory, because the planned per-segment wind (v_par) and grade are NOT persisted with the recorded ride and cannot be recovered from the GPX alone — so rides finished before this story, or after a reload with no loaded plan, contribute nothing. (c) Only aggregated buckets are persisted (weighted sums keyed by surface + v_par band + grade band), never raw points, and band edges sit on the model's kinks (0 for wind, 0 for grade) so no bucket mixes headwind with tailwind or up with down. (d) Applying a calibrated model is an explicit owner action in Settings (acceptance: no silent changes); planning reads `activeSpeedSettings()`, which overlays the applied model onto defaults. (e) The before/after ETA-error comparison is computed over the calibrated paved/gravel portion of the buckets — exactly the portion any calibration can change. **Review addendum** (substitute Opus review, standing in for Fable 5 — out of credits): the bound `k_head ≥ k_tail ≥ 0` is enforced only among *fitted* parameters, so a held (unfitted) coefficient stays exactly at base instead of being dragged along by the projection — an honest partial fit; the fit and its input observations now run on the moving-time clock (`MOVING_SPEED_MS` gate applied in `observationsFromRide`, matching `summary.movingS`); the fit and before/after comparison are restricted to near-flat buckets (`MAX_FIT_GRADE_PCT`, 4%) so descent error can't leak into `v0` — steep buckets are still persisted for a future physics-model story; per-ride ETA error is scored by `etaErrorForModel` over the ride's own buckets (the portion actually ridden), making it coverage-robust against early-bailed rides; and a persisted applied model is validated (all params finite) before it can drive ETAs, falling back to defaults otherwise. | DECIDED |
| DEC-029 | **Forecast-robustness design** (WR-025). (a) The robustness spread is surfaced as extra effective headwind in m/s (`evidence.robustnessSpreadMs`) — an absolute, bounded metric, not a relative %, because a relative measure would explode on routes with near-zero headwind at the exact forecast. (b) The Results-card robust/fragile UI threshold is `ROBUST_SPREAD_THRESHOLD_MS = 0.5`. (c) Robustness is computed inside `scoreMatrix` as well as `scoreCandidates`, passing the same wind + `startHourIndex` into the rotated passes, so the start-time heat-strip totals stay consistent with the main ranking rather than silently omitting the sub-score. (d) Ranking ties break toward higher robustness, then candidate id. (e) The worst case is the MAX headwind penalty over `{−30°, 0°, +30°}` (equivalently the MIN WindComfort), reusing fixed geometry/segments across the two extra re-analyses — within the story's <2× scoring-cost budget. **Review addendum** (substitute Opus review, standing in for Fable 5 — out of credits): the Results-card marker is quality-neutral — "forecast-stable" / "forecast-sensitive" — decoupled from route quality, because forecast-INSENSITIVITY is not goodness (a uniformly bad route, e.g. pure headwind at every rotation, is also stable); only the sensitive case is coloured as a caution, stable is muted. The displayed spread (`evidence.robustnessSpreadMs`) is the un-emphasised effective headwind in m/s, while the ranking penalty keeps the direction-emphasis weighting — the card shows an honest wind figure, the score keeps the product's emphasis logic. | DECIDED |

| DEC-031 | **Winter/Nordic mode design** (WR-027). (a) Season suggestion is temperature-based (≤ +3 °C, `WINTER_SUGGEST_TEMP_C`); the manual toggle is always authoritative over the suggestion. (b) Ice-risk heuristic = coldest window hour ≤ +1 °C (`ICE_RISK_TEMP_C`) AND precipitation > 0 in the prior 24 h — advisory only, always phrased "possible ice — ride like it's there", never a guarantee; friction/road-maintenance modelling stays out of scope. (c) Precipitation type is temperature-inferred (≤0 °C snow, ≤2 °C sleet, else rain) since `WindSample` carries no snowfall field to read directly; the rain sub-score itself is unchanged — winter only changes the copy (snow ≠ rain), not the scoring. (d) Studded-tyre offset is −3 km/h (`STUDDED_OFFSET_KMH`) off every surface's base speed, floored at `minKmh`. (e) Winter mode defaults "home before dark" ON; daylight remains the existing SCORING_SPEC §5 hard constraint — winter changes its default, not its mechanism. (f) Shaded/icy stretches are `exposure ≤ 0.5` (`ICY_SHADE_EXPOSURE_MAX`), reusing the WR-018 exposure grid as a shade proxy. (g) The weather adapter gains an optional `recentPrecipMm` via Open-Meteo `past_hours=24`; its absence (e.g. mock provider without a fixture story) is treated as 0 rather than failing the plan. **Review addendum** (substitute Opus review, standing in for Fable 5 — out of credits): winter wiring is now covered by `runPlan`-level integration tests (daylight forced on even with the user toggle off, studded speeds slow the same route, the ice caution fires/doesn't correctly), not just engine-level unit tests; studded tyres also raise rolling resistance (`crr × WINTER_CRR_MULT`, 1.3) so the physics speed model slows down too, not just the Newton-seed `baseKmh`; the ice caution uses the `--cross` caution hue, not the `--head` headwind hue; precipitation type is inferred at the departure hour, not hour 0; and `recentPrecipMm` sums only the prior N hours, excluding the trailing forecast hour Open-Meteo also returns. | DECIDED |
