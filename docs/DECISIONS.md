| DEC-020 | WR-011's acceptance harness drives the **real product pipeline** (`runPlan`), not a bespoke re-implementation. Through the product's actual budget-limited 6–8 loop candidates (mock synthetic loops, uniform SW-8 wind, loop-cancellation, limited `MockRouteProvider` ellipse shape variety), the honest winner-beats-median time-weighted headwind margin is **~6%** (30/50/80 km all ~6%), not PRODUCT_SPEC §6's 15% target. An earlier bespoke 16-candidate over-generation had wrongly measured this at ~12–13%; that figure was an artifact of over-generating candidates outside the product's real pipeline and is retired. The gate floor is set to **5%** — a meaningfulness floor proving the ranking genuinely favours low headwind and catches inversions, explicitly *not* a claim of meeting the 15% product bar. Real ORS road networks are expected to differ far more per candidate than the mock ellipses. The 15% PRODUCT_SPEC §6 target must become an explicit acceptance item on whichever future story captures the real ORS fixtures (DEC-013). | DEFAULT-open |
| DEC-021 | Off-route reroute near the finish (WR-015, Fable 5 review fix): when the rejoin point (`progress + REJOIN_AHEAD_M` = 500 m) would fall within `FINISH_GUARD_M` (50 m) of the route finish, do **not** reroute — stay in the bearing-to-track alert instead. NAVIGATION_SPEC §3 forbids rerouting to the finish, and this near the end there is essentially no chosen route left to preserve; a beeline-to-finish leg would both violate the rule and shortcut remaining distance. Consequence: `Rerouter.attempt` returns `{ ok: false, reason: 'near-finish' }` (no `pointToPoint` call) instead of attempting a reroute. | DECIDED |
| DEC-022 | **Live off-route auto-reroute deferred** (WR-016, Fable 5 review fix). Decision: WR-016 ships off-route DETECTION (WR-013/015) plus an audible alert (announced once per off-route episode) and a bearing-to-track guidance arrow (`RideState.toTrack`), but NOT the full auto-reroute that splices a new leg into live navigation. Rationale: `spliceRoute` (WR-015) produces a geometry-only `CandidateRoute` with no `CandidateAnalysis`, and the `RideController`'s ETA/wind-HUD need per-segment analysis (wind sample, modelled speed/time); re-analysing the spliced route live (reusing nearest-segment wind samples per WR-015's out-of-scope note) is a non-trivial addition, not a wiring task. Consequence: the tested WR-015 `Rerouter`/`spliceRoute` building blocks remain available and unused live; a follow-up story will wire monitor → `Rerouter.attempt` → `spliceRoute` → re-analyse the new leg → swap route/track/snapper + `CueScheduler.rearm` + `announcer.stop()`. Until then the rider gets the alert + bearing arrow and rejoins manually. | DECIDED |

| DEC-025 | Shelter axis gated on real grid data (WR-019, Fable 5 review fix). Decision: the Shelter sub-score (`scoreCandidates`) is normalized across candidates only when `ScoreOptions.hasShelterData` is true — i.e. a real exposure grid covered the routes; otherwise every candidate gets the uniform neutral 0.5. Rationale: the neutral-0.5-for-no-upwind convention (mirroring `seqShare`) combined with `normalizeHigher` would otherwise turn mere presence-of-headwind (raw `shelterShare` 0 vs the neutral 0.5) into phantom shelter differentiation when no grid exists at all — double-counting the wind axis with data that doesn't exist. Consequence: shelter contributes nothing to ranking until the WR-018 grid is generated (DEC-024); raw `shelterShare` is still computed and surfaced as evidence (`explain.ts`, evidence fields) regardless of the gate. | DECIDED |
| DEC-026 | **CrosswindSafety narrowed to exposed ≥13 m/s gust stretches** (WR-021, review-pass fix; reviewed by a substitute senior reviewer on Opus — Fable 5 was out of usage credits this session). Decision: `CrosswindSafety` no longer penalizes ordinary/mild crosswind on a per-segment threshold; it only penalizes time spent inside flagged stretches — exposure ≥ 1.0 AND gust_eff ≥ 13 m/s (settings 10–18) AND v_cross ≥ 0.6·W_eff, merged across calm gaps < 150 m into runs ≥ 300 m (`engine/gustFlags.ts`, single source shared with the results chip, ride HUD, and map markers). This is an intentional narrowing — mild crosswind is no longer penalized at all; only exposed, strongly gusty, mostly-crosswind corridors count — and it changes candidate rankings versus the old per-segment cross-threshold rule. **Supersedes DEC-015's `crossThreshold = 5 m/s` default**: `ScoreOptions.crossThresholdMs` is now `@deprecated` in favour of `ScoreOptions.gustThresholdMs`. | DECIDED |
| DEC-027 | **Strava upload: sanctioned GET + idb-stored secret** (WR-023). The story's acceptance criteria say "absolutely no Strava reads anywhere" / "no GET endpoints" — but Strava's upload API requires polling `GET /uploads/{id}` to learn the resulting `activity_id`; there is no non-GET way to obtain it. Decision: this single GET is sanctioned as part of the write flow, not a data read — it returns only the status of the upload WE just pushed (`id`, `activity_id`, `error`), never athlete/activity/segment data, so the ToS/CLAUDE.md upload-only rule (Strava data must never enter scoring or any ML/AI path) is upheld. `StravaUploader`'s adapter test asserts every mocked GET call targets `/uploads/{id}` and nothing else. Second, the Strava client secret and refresh token live in **idb at runtime** (owner-entered via `StravaSettings`, sourced from `tools/.strava.json` written by `tools/strava-auth.mjs`), **not** in Vite env — a client-only PWA with no backend must be able to refresh its own access tokens, and Vite env values are bundled into the shipped app, which the secret must never be. "Never bundled in Vite env" is the constraint actually being honoured; idb is the sanctioned alternative store. **Follow-up (WR-023 review pass):** browser-direct calls to Strava's `/oauth/token` and `/uploads` may be blocked by CORS (no guaranteed `Access-Control-Allow-Origin` for browser callers) — unverified until the manual end-to-end runs. If a proxy turns out to be required, it would also move the client secret server-side, superseding this idb-secret arrangement. | DECIDED |
